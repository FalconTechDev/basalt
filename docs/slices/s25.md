## Classification

**Third-party library items: none.** Every item in `ITEMS.json` is application code — the Bases
(database) feature's toolbar dropdown menus, property/sort/group rows, view chooser and
configuration pages, grouped query-result data, the small formula editor with its suggester, the
Bases file view and the new-item button. The six short names `zX qX _X XX JX r$` are localization
aliases (`gm.plugins.bases` / `gm.plugins.fileExplorer`); they were already covered by declarator
entries merged with slice s09, so this slice adds no declarators of its own.

**Application items: all 27.** 21 replaced as own classes via `classes` manifest entries
(46 534 original bytes), 6 already covered by existing `declarators` entries.

## Bugs found and fixed during verification

- `GroupRow is not a constructor` / `ViewChooser`/`PropertyEditPage` failures: factory-time
  captures of sibling own classes declared later in the bundle — switched to lazy `host.*` lookups.
- `child.load is not a function` on view open: `ViewsMenu` (`s$`) was missing `inherit(ViewsMenu,
  Component)`; the other IIFE-style classes (`AX QX t$ c$ u$ UX PX`) intentionally have no base.

## Known issues / limitations

- **Pre-existing quirk (not a regression)**: with a `.base` file whose query fails to parse, the
  inherited filter builder (`EX`, still minified) throws `undefined.funcName` inside
  `operatorComponent.value` during `notifyView`-debounced `updateQuery`. The same unguarded
  `controller.query.views` / `controller.app` accesses exist in the original classes, so behaviour
  matches `ca5acac`; observed only while a deliberately malformed test file was loaded.
- A second stale workspace leaf on the same `.base` file (test-vault artifact of reopening) keeps
  `queryController/query` unset until its first successful `update()`; programmatic `setOpen` on its
  menus reproduces the same unguarded-access crashes the original code would produce. The visible,
  updated leaf works cleanly.
- Differential run against `ca5acac` was not performed; verification is build checks + smoke +
  scripted CDP scenarios on the isolated runtime.
