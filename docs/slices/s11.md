## Notes

- Own classes that inherited code subclasses are written as constructor functions and linked
  with `src-app/inherit.js` (`Object.setPrototypeOf` + `Object.create`), matching the
  ES5-style `Base.call(this)` convention of the remaining bundle.
- All host access goes through the lazy `env()`/`__basaltHost` thunks; `envBind` entries are
  emitted as getters so late-bound app values (e.g. `activeWindow.electronWindow`) are never
  read during module evaluation.
- `new env().X(...)` is a call, not a construction (`env()` is a CallExpression, so `new`
  binds only to `env`); own code must write `new (env().X)(...)`. All such sites in
  `src-app/` were fixed.
