# План: живое выполнение кода на большинстве языков и выход на GitHub

## Часть 1. «Выполнение» для большинства языков

Вместо отдельного трассировщика под каждый язык используется один клиент **DAP** (Debug Adapter Protocol). Это тот же протокол, через который отлаживает VS Code. Код Basalt пишется один раз, а для языков ставятся готовые адаптеры.

| Язык | Адаптер | Как запускается |
|---|---|---|
| Python | debugpy | `python -m debugpy.adapter` (`pip install debugpy`) |
| JS / TS (Node) | js-debug (vscode-js-debug, MIT) | входит в поставку Basalt |
| Rust, C, C++, Zig, Swift | lldb-dap (из LLVM) или CodeLLDB | нужна сборка с отладочной информацией (`cargo build`) |
| Go | Delve (`dlv dap`) | `go install github.com/go-delve/delve/cmd/dlv@latest` |
| Dart / Flutter | `dart debug_adapter` / `flutter debug_adapter` | входит в Dart SDK |
| Java / Kotlin | java-debug (через jdtls) | второй этап |
| C# | netcoredbg | второй этап |
| Ruby, PHP, Lua | rdbg, Xdebug, local-lua-debugger | по запросу |

### Режимы просмотра (общие для всех языков)

- **Живой.** Раз в 30–100 мс программа ставится на паузу на несколько миллисекунд. За это время забираются `threads` и `stackTrace`, затем выполнение продолжается. На экране:
  - цепочка «файл › функция › строка», которая сейчас работает;
  - подсветка строки в коде;
  - счётчики, в каких функциях программа проводит время.
- **Пошаговый.** Шаги `next` и `stepIn` выполняются с заданной задержкой (30 мс, 150 мс или 0,6 с на шаг). Видна каждая строка, как в прошлой версии для Python.
- **Пауза и продолжение, точки остановки по клику в коде.** Даются протоколом бесплатно.

### Шаги

1. `src/basalt-dap.js`: клиент DAP. Транспорт через stdio и TCP, запросы `initialize`, `launch`, `pause`, `stackTrace`, `continue`, `next`, `disconnect`.
2. `src/basalt-run-langs.js`: таблица языков (расширение файла → адаптер → аргументы запуска). Проверка, установлен ли адаптер. Если нет, показывается кнопка с командой установки.
3. Вид «Выполнение» (вернуть из отменённого коммита f466923). Вместо питоновского трассировщика он подключается к DAP. Интерфейс остаётся прежним: цепочка слева, код в центре, функции справа, вывод программы внизу.
4. Проверка на демо-проекте из 2–3 файлов для каждого языка первой волны: Python, JS, Rust, Go, Dart. Цепочка и строки должны совпадать с реальным выполнением.
5. Вторая волна: Java, Kotlin, C#, Ruby, PHP.

Ограничения, о которых нужно сказать пользователю:
- Rust, C и C++ нужно собирать в отладочном режиме.
- Живой режим основан на выборке, поэтому очень короткие функции могут не попасть в кадр. Счётчики точны только в пошаговом режиме.

## Часть 2. Выход на GitHub

### Блокер

Basalt — изменённая копия Obsidian 1.12.7. Лицензия Obsidian запрещает распространять приложение и изменять его (`LICENSE`, `docs/CORE-REWRITE.md`).
- В git сейчас отслеживаются около 350 файлов Obsidian, примерно 28 МБ: `src/lib`, `src/i18n`, `src/sandbox`, `src/public`, `main.js`, `starter.*`, `worker.js`, `sim.js`.
- Файл `app.js` уже в `.gitignore`.
- Выложить репозиторий как есть и установщик с этим кодом нельзя: такой репозиторий удалят по DMCA.

### Варианты

- **A. Открыть только своё (можно сразу).** Публичный репозиторий содержит Rust-движки (canvas, search, graph, pty, cli), `plugins-sdk`, `basalt-*.js`, `fp-*.js`, `vault-sync.js`, скрипты сборки. Чужое ядро не выкладывается и в релизы не входит. Собрать приложение из такого репозитория без своей копии Obsidian нельзя, и это честно указывается в README.
- **B. Полный открытый релиз с установщиком.** Сначала нужно заменить ядро по `docs/CORE-REWRITE.md`:
  1. оболочка (вкладки, проводник, настройки);
  2. редактор (CodeMirror 6);
  3. модель холста;
  4. API плагинов;
  5. `main.js`.

  Это большая работа, но только так получится настоящий продукт.

Рекомендация: начать с варианта A, параллельно вести B, и выпустить установщик, когда B закончится.

### Чек-лист перед публикацией

1. Новый чистый репозиторий без старой истории: в истории git остаются файлы Obsidian, а `.git` весит 22 МБ. В него переносятся только свои файлы.
2. Удалить или исключить чужое:
   - перечисленные выше папки;
   - `runtime/` (328 МБ, Electron), `dist/`, `data/`.
3. Проверить секреты: токены, личные пути `C:\Users<имя>`, адреса хранилищ, `tg_session`. Прогнать `gitleaks` по новому репозиторию.
4. Выполнить `node tools/obsidian-audit.mjs`: в своих файлах не должно остаться упоминаний Obsidian (сейчас их 626).
5. README:
   - что это и скриншоты;
   - что открыто, а что нет;
   - как собрать движки (`cargo`, `node build-canvas.mjs`).
6. Проверить `LICENSE` (MIT для своих файлов) и `THIRD_PARTY.md` (лицензии всех вендорных библиотек: CodeMirror, lucide, адаптеры DAP).
7. CI в GitHub Actions: `cargo build` и `cargo test` движков, проверка JS-синтаксиса `basalt-*.js`.
8. Шаблоны issue, `CONTRIBUTING.md`, описание репозитория, теги, социальная картинка.
9. Каждая публикация проходит через `pubpace` (паузы между публикациями).
